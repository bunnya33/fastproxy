# FastProxy 架构约定

数据通路：客户端 → 本机 IPv4 监听端口 → DNAT → 目标 IPv4 和端口 → SNAT/MASQUERADE → 目标服务器。返回数据由 Linux conntrack 自动反向转换并交给客户端，管理服务不搬运业务数据。

- 支持 TCP、UDP，以及同一端口同时转发两种协议。
- 应用数据保持不变。目标服务器通常看到转发服务器的地址；首版不支持保留客户端源地址、跨 IPv4/IPv6 转换或动态域名目标。
- 默认监听全部本机 IPv4，也可指定一个本机 IPv4。仅匹配目的地址属于本机的数据，不劫持经过此机器的其他流量。
- 一条规则包括名称、协议、监听 IP/端口、目标 IP/端口、启用状态。开启的规则不允许监听端点重叠。管理端口和配置的 SSH 端口受到保护。
- Web 后台和 `fastproxy` 菜单调用同一套服务 API。网页需要登录和 CSRF 校验；本机控制台通过仅 root 可访问的 Unix socket 管理。
- 修改前检查规则，随后持久化意图并使用 `nft -c -f` 校验。通过后一次性替换专属 `ip fastproxy` 表；失败恢复磁盘规则，内核事务不会部分生效。启动时从磁盘重新应用。
- 不使用 `flush ruleset`，不接管 UFW、firewalld、Docker 等其他规则。其他防火墙仍可能拒绝 FORWARD 流量，需要管理员放行；专属表里的 accept 无法覆盖其他表的 drop。
- NAT 规则影响新连接。修改、停用、删除或正常停止服务后，既有 conntrack 会话可能继续到超时；正常停止会移除 FastProxy 表，异常退出后表可能保留，重启将重新应用磁盘配置。
- 流量计数来自内核双向 FORWARD 计数器，每次规则发布或服务重启会重置。不将内核安装成功误报为目标服务可用。
- systemd 开机启动并负责异常重启；规则文件位于 `/var/lib/fastproxy/state.json`，操作记录为 `audit.jsonl`，服务日志在 journal。

后台面向运维人员，推荐通过 SSH 隧道或 HTTPS 反向代理访问。默认管理地址只绑定 `127.0.0.1:8080`。
